# VoiceX 翻译并朗读（Translate & Read）需求文档

> 文档状态：需求基线，按此实现
> 日期：2026-09-16
> 前置：选中朗读功能已上线，见 `tts_plan.md`；本文只描述在其之上新增的能力

## 0. 决策摘要

以下是讨论后已定的结论，正文各节展开。

| 主题 | 决策 |
|---|---|
| 功能形态 | 在"取到选中文字"和"交给 TTS"之间插入一次大模型调用，独立快捷键触发 |
| 大模型选择 | 朗读页一个下拉，选项与大模型页的 provider 下拉一致，另加"跟随大模型设置"；翻译朗读与普通朗读预处理共用这一项 |
| 语言 | 源语言默认自动检测；目标语言固定列表，简繁分开 |
| 提示词 | 模板含语言占位符，运行时按配置填充；默认提示词面向"可朗读的纯文本"而非面向翻译 |
| 音色 | 翻译朗读可按 provider 单独指定音色，留空沿用朗读音色；语速音量沿用 provider 的朗读设置 |
| 失败处理 | 翻译失败、超时、模型未配置：HUD 报错并且不朗读，不回退朗读原文 |
| 长文本 | M1 设字数上限，超限 HUD 提示；M5 流式后取消上限 |
| HUD 状态 | 新增"翻译中"阶段，用魔法棒图标；右侧标签显示绿色"翻译朗读" |
| 字幕 | 句子级同步，靠播放进度而不是厂商时间戳；M3 起只给翻译朗读，后续两种朗读都允许；系统默认音色 say 不显示字幕 |
| 字幕版式 | 先出基本功能，再打磨：加宽、加大字体、无外框只显示文字 |
| 结果留存 | 翻译后可复制到剪贴板（默认关）、写入历史（默认开），均为开关 |
| 普通朗读预处理 | 新增"朗读前用大模型整理文本"开关，默认关，带默认提示词 |
| 流式 | 大模型流式输出逐句送 TTS 并驱动字幕，列入需求，放在最后一个里程碑 |
| 不做 | 逐字高亮；一句一个 say 进程；自由文本语言输入 |

## 1. 背景与目标

现有朗读功能把选中文字原样送入 TTS。用户阅读外语内容时，希望按一个快捷键，听到的是翻译后的目标语言，并且能看到正在朗读的译文。同时，选中的文本经常是 Markdown 或 HTML 源码，直接朗读会把标记符号读出来，普通朗读也需要一次可选的大模型整理。

目标：

- 翻译朗读：选中 → 翻译 → 朗读，独立快捷键、独立语言与音色设置。
- 字幕：翻译朗读时在 HUD 显示当前朗读的句子，句子级同步。
- 普通朗读预处理：可选的大模型整理，去掉不可朗读的标记。
- 译文留存：可复制到剪贴板、可写入历史。

## 2. 范围与里程碑

| 里程碑 | 内容 | 说明 |
|---|---|---|
| M1 翻译朗读核心 | 设置项、快捷键与三方冲突、翻译阶段、音色覆盖、HUD 翻译中状态与标签、失败处理、字数上限、剪贴板与历史 | 无字幕，沿用紧凑版 HUD |
| M2 普通朗读预处理 | 开关、默认提示词、共用大模型选择、失败回退 | 复用 M1 的大模型阶段 |
| M3 字幕基础 | 句级分块、播放进度回报、字幕事件、带文字的 HUD 版式加宽 | 仅翻译朗读；系统默认音色不显示 |
| M4 字幕打磨 | 大字体、无外框、位置与透明度 | 视觉迭代，可多轮 |
| M5 流式 | 大模型流式输出 → 逐句 TTS → 字幕；取消字数上限；直接朗读也可显示字幕 | 高级功能 |

每个里程碑单独成 PR。M1 与 M2 可以合并为一个 PR，如果改动量可控。

## 3. 功能需求

### 3.1 触发与快捷键

- 新增独立的全局快捷键"翻译并朗读"，默认 Option+Command+T，可录制、可重置，与朗读键的设置 UI 一致。
- 冲突检测扩展为三方互查：听写、朗读、翻译朗读两两不能相同。冲突时按现有做法禁用后绑定的那个并在设置页说明。
- 行为与朗读键一致：有朗读会话在进行时，按下任一朗读键都是停止当前会话，而不是切换成另一种朗读；空闲时按下才开始。
- "翻译中"阶段按快捷键或 Escape 要能取消正在等待的大模型请求，取消后不朗读。
- 听写录音进行中，翻译朗读键与朗读键一样被吞掉。
- 翻译朗读有独立的总开关。关闭时不绑定快捷键，键位交还给前台应用。

### 3.2 语言

- 源语言：默认"自动检测"，可选固定列表中的语言。显式指定只在自动检测有歧义时有价值，例如中日汉字、简繁。
- 目标语言：固定列表，默认英语。初始列表：简体中文、繁体中文、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语。
- 语言代码到自然语言名的映射由代码维护，填入提示词时用英文名加本地名，例如 `Simplified Chinese (简体中文)`，这样无论提示词是中文还是英文模板、无论哪家模型都能稳定理解。
- 原文已是目标语言时，由提示词规则决定只做格式整理不翻译，不在本地做语言检测。

### 3.3 大模型选择

- 朗读页新增一个"大模型"下拉，选项与大模型页 provider 下拉完全一致：火山、OpenAI、千问、Gemini，以及每个命名的自定义端点。另加一个默认项"跟随大模型设置"，取大模型页当前激活的 provider。
- 凭证、模型名仍在大模型页维护，朗读页只引用，旁边放一个跳转链接。
- 这一项由翻译朗读和普通朗读预处理共用。
- 选中的 provider 没有 API Key 时，触发翻译朗读在 HUD 报"模型未配置"，不朗读。
- 后端需要一个按 provider key 构建 `LLMConfig` 的函数，替代现在只认全局激活 provider 的做法。

### 3.4 提示词

- 翻译朗读提示词和预处理提示词各一份，用户可编辑，可恢复默认。默认文案分中英两份，随界面语言选择，沿用现有 `isBuiltInDefaultPrompt` 的判定方式。
- 翻译朗读模板含 `{{SOURCE_LANGUAGE}}` 与 `{{TARGET_LANGUAGE}}` 占位符，运行时按设置填充。用户编辑后的模板若缺少占位符，运行时在末尾补一行语言说明，与现有词典占位符缺失时的追加行为一致。
- 默认提示词面向朗读：输出必须是可朗读的纯文本。去掉 Markdown 与 HTML 标记；链接只留文字不读 URL；表格改写成句子或跳过；代码块跳过；脚注序号、引用标记、图片语法去掉；保留专有名词、数字、单位。草案见附录 A。
- 大模型调用的用户消息不再使用现有的"原文："前缀，改用中性包装，避免给翻译任务带来语言偏置。
- 现有听写翻译的提示词与设置不动，翻译朗读是独立的一套。

### 3.5 音色

- 翻译朗读沿用朗读页选中的 TTS provider 与凭证，可单独指定音色。音色覆盖按 provider 存一份，阿里云按模型再分，留空表示沿用朗读音色。
- 音色选择器按目标语言过滤，音色列表已带 language 字段。系统音色列表来自 AVSpeech，同样可过滤。
- 语速、音量、音调沿用该 provider 的朗读设置，不另存。
- 设置页在有效音色的语言与目标语言不匹配时给出提示，不阻止保存。
- 系统 provider 下留空意味着走 `say` 的默认音色，它跟随系统"朗读内容"语言，读外语效果差，设置页说明这一点。

### 3.6 翻译阶段行为

- 超时沿用现有按字数放大的策略，起步 10 秒、上限 60 秒。
- 失败、超时、模型未配置：HUD 显示对应错误文案，不朗读，不回退朗读原文。错误码至少三类：`llm_not_configured`、`llm_failed`、`llm_timeout`。
- 字数上限：M1 取 3000 字符，超限在 HUD 提示"选中文字过长"，不发请求。上限是代码常量，不做设置项。M5 流式后取消。
- 翻译结果为空或与预期不符不做本地校验，直接朗读。
- 翻译阶段与后续朗读共用一个会话令牌，取消语义与现有朗读相同。

### 3.7 HUD 状态与区分

- 朗读状态事件增加 `kind` 字段区分直接朗读与翻译朗读，`phase` 增加 `translating`。
- 翻译中：图标切成听写校正用的魔法棒，TTS 出声后换回朗读图标。紧凑版下没有文字区，图标切换就是唯一信号；带文字的版式下文字区显示"正在翻译..."占位。
- 右侧标签：直接朗读显示"朗读"，翻译朗读显示绿色"翻译朗读"，配色沿用听写翻译。
- 错误显示复用现有路径，只补文案。
- 普通朗读预处理进行中同样显示魔法棒，标签仍为"朗读"。

### 3.8 字幕

适用范围：M3 起只在翻译朗读时显示；后续开放给直接朗读，开关不区分朗读种类。

同步机制：

- 待朗读文本按句切成小段，段长上限约 120 字符，沿用 `split_for_backend` 的"先句末、后子句"规则。每段作为一个 TTS 请求或一个 AVSpeech utterance。
- 云端后端记录每段音频在播放流中的起始采样位置，播放器已知已消费采样数，两者比较得出当前段。四家云端后端同一套机制，不依赖厂商时间戳接口。
- AVSpeech 后端每段一个 utterance，用 delegate 的开始回调标记当前段。
- `say` 后端没有进度信号，不显示字幕，HUD 保持紧凑版。
- HUD 驱动线程按现有 60 ms 轮询读取后端当前段，变化时发字幕事件，载荷为当前句文本、下标、总数。

版式：

- M3：新增一种带文字的 HUD 呈现，窗口加宽到 400 左右，两到三行，显示当前句。
- M4：加大字体，无外框只显示文字，位置与透明度可调，与现有 `hudTransparent` 设置协调。这一步以视觉效果为准，允许多轮迭代。

风险：句级分块让云端请求数增加。CosyVoice 已经以 120 字分块运行，衔接没有问题；其他后端在实现时验证请求频率是否触发限流。

### 3.9 译文留存

- 复制到剪贴板：开关，默认关。翻译成功后把译文以纯文本写入剪贴板，不恢复。取词的剪贴板降级在翻译之前已完成快照与恢复，两者不冲突。
- 写入历史：开关，默认开。记录 `mode` 为 `translate_read`，`text` 为译文，`originalText` 为原文，`llmModelName` 为所用模型，无音频。历史页需要为该 mode 增加展示分支。译文只存本机：不进同步队列，不计入总输入字符数、AI 纠错次数和本机设备统计，删除时也不发同步事件（2026-09-16 决定，见附录 B.2）。
- 普通朗读及其预处理不写历史。

### 3.10 普通朗读的大模型预处理

- 开关"朗读前用大模型整理文本"，默认关。
- 默认提示词：不翻译、不改语义，只做与 3.4 相同的格式整理。草案见附录 A。
- 使用 3.3 的共用大模型选择。
- 失败或超时：记录日志并朗读原文。这里与翻译不同：原文与整理结果是同一内容，朗读原文只是多读几个符号，用户仍能理解。
- 超时策略与翻译相同。
- 翻译朗读的提示词已包含格式整理，因此一次朗读最多一次大模型调用。

### 3.11 平台

- 选中文字读取只有 macOS 实现，翻译朗读继承这一限制。其他平台不绑定快捷键，设置页沿用现有"Windows 暂不支持"的说明方式。
- 大模型与云端 TTS 部分本身跨平台，选区读取的 Windows 实现是独立课题。

## 4. 设置项

前端键名与后端字段一一对应，后端用 `serde(default)` 兼容旧配置。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `ttsTranslateEnabled` | boolean | true | 翻译朗读总开关，控制快捷键绑定 |
| `ttsTranslateHotkeyConfig` | string \| null | null | null 表示默认键位 |
| `ttsTranslateSourceLanguage` | string | `auto` | `auto` 或语言代码 |
| `ttsTranslateTargetLanguage` | string | `en` | 语言代码 |
| `ttsTranslatePromptTemplate` | string | 默认提示词 | 含占位符 |
| `ttsTranslateVoiceOverrides` | Record<string, string> | `{}` | 键为 provider，阿里云为 `aliyun:<model>`；值为音色 id；缺省沿用朗读音色 |
| `ttsTranslateCopyToClipboard` | boolean | false | 译文复制到剪贴板 |
| `ttsTranslateSaveHistory` | boolean | true | 译文写入本机历史（不同步、不计统计） |
| `ttsLlmProviderKey` | string | `follow` | `follow`、内置 provider 名，或 `custom:<id>` |
| `ttsPreprocessEnabled` | boolean | false | 普通朗读前大模型整理 |
| `ttsPreprocessPromptTemplate` | string | 默认提示词 | |
| `ttsCaptionsEnabled` | boolean | true | 字幕开关，M3 起生效 |

大模型设置页同时新增推理控制（附录 B 的实测结论），不带 `ttsTranslate` 前缀，因为听写整理同样受益：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `llmCustomEndpoints[].reasoningEffort` | string | `''` | 空串不发送；否则原样作为 `reasoning_effort` 发给自定义端点 |
| `llmCustomEndpoints[].extraBody` | string | `''` | JSON 对象，合并进每个请求体，同名键覆盖；不是合法 JSON 对象时请求报错而不是静默忽略 |
| `llmOpenaiReasoningEffort` | string \| null | null | OpenAI 官方端点的 `reasoning_effort`，null 不发送 |

命名用 `ttsTranslate*` 前缀，与听写翻译的 `translation*` 区分。现有 `translationTargetLanguage` 属于听写翻译且未被使用，本需求不动它。

## 5. 涉及模块与改动点

- 快捷键 `src-tauri/src/hotkey/`：第三个绑定、三方冲突、状态结构扩展、新的 hook 事件。
- 朗读控制 `src-tauri/src/tts/controller.rs`：朗读种类枚举；在取词与朗读之间插入大模型阶段，运行在会话令牌下可取消；音色覆盖解析；字幕段的切分与当前段回报。
- 大模型 `src-tauri/src/llm/`、`services/llm_service.rs`：按 provider key 构建配置；独立于 `correct` 的通用补全入口，不注入词典与"原文："前缀；M5 增加流式。
- TTS 后端 `src-tauri/src/tts/*.rs`、`playback.rs`：按段请求、记录段起始采样、暴露当前段；AVSpeech 每段一个 utterance。
- HUD `src-tauri/src/services/hud_service.rs`、`src/hud/`：`translating` 阶段与 `kind`；字幕事件；带文字的朗读呈现与尺寸；M4 视觉打磨。
- 历史 `services/history_service.rs`、`src/views/History.vue`：`translate_read` 记录与展示。
- 设置 `commands/settings.rs`、`src/stores/settings.ts`、`src/views/ReadingSettings.vue`、`src/i18n/locales/`：第 4 节的键、朗读页新小节、中英文案。
- 提示词 `src/utils/llmPrompts.ts`：两份新默认提示词、占位符填充与语言名映射。

测试：分块与占位符填充用单元测试覆盖；三方冲突用现有冲突测试模式扩展；真机验证走 `scripts/tts/` 的注入方式，覆盖翻译成功、失败、取消三条路径与字幕跟随。

## 6. 流式方案（M5）

- 大模型客户端支持流式响应：OpenAI 兼容接口走 SSE，Gemini 走流式生成接口。
- 流式文本进入句子检测器，凑满一句就作为一段送入 TTS 队列，TTS 后端从固定段列表改为可增长的队列。
- 字幕随段推进，机制与 M3 相同。
- 第一句翻完即开始朗读，长文本不再需要字数上限。
- 同一机制让直接朗读在开启预处理时也能边整理边朗读。

## 7. 不做的事

- 逐字高亮。只有 AVSpeech 回调与部分云端的时间戳参数能给逐字信息，四家后端表现不一。
- 一句一个 `say` 进程。句间会有可听的启动间隙。
- 自由文本的语言输入。固定列表足够，且映射需要代码维护。
- 本地语言检测。交给提示词规则。

## 8. 默认值清单

以下默认值是本文的选择，实现前可以调整，调整不影响其余设计：

- 默认快捷键 Option+Command+T
- 目标语言初始列表见 3.2，默认英语
- 翻译字数上限 3000 字符
- 字幕段长上限 120 字符
- 写入历史默认开，复制剪贴板默认关，字幕默认开

## 附录 A 默认提示词草案（zh-CN）

英文版在实现时对照翻译。

### A.1 翻译朗读

```
你是一个翻译助手。你输出的文字会被直接送入语音合成引擎朗读，因此必须是可以顺畅朗读的纯文本。

源语言：{{SOURCE_LANGUAGE}}
目标语言：{{TARGET_LANGUAGE}}

你的任务：
1. 将输入文本翻译成目标语言，保留原意、语气和信息量；不增删内容，不解释，不评论
2. 如果输入已经是目标语言，不要翻译，只做下面的格式整理
```

### B.1 推理预算与输出上限（2026-09-16 补充）

- 根因修正：截断不是模型上下文不够，而是应用自己给 OpenAI / Qwen / Gemini / 自定义端点硬编码了 4096 的输出上限（`max_tokens` / `max_completion_tokens` / `maxOutputTokens`），推理模型把它花在思考上，正文就没了。火山引擎一直没发上限，所以从未出现。
- 已实现：删掉所有固定输出上限；按 `tools/llm-bench` 的做法，自定义端点各自带 `reasoning_effort` 与 `extra_body`（JSON 对象合并进请求体、同名键覆盖、非法 JSON 报 `InvalidConfig`），OpenAI 官方端点带可选 `reasoning_effort`。默认都不发送，尊重服务端默认。
- 逐端点实测（走应用自己的请求构造，`VOICEX_DB` 指向设置库副本，2900 字中文）：

| 端点 | 不发开关 | 有效开关 | 结果 |
|---|---|---|---|
| Cerebras `qwen-3.8-27b` | 3.2 秒，完整 | `reasoning_effort: none` | 1.4 秒 |
| Deepseek `deepseek-v4-flash` | 8.8 秒，完整（默认思考，短文本 583 个推理 token） | `reasoning_effort: none` 或 `{"thinking": {"type": "disabled"}}` | 6.2 秒；短文本推理 token 0，1.6 秒 |
| Xiaomi `mimo-v2.5` | 60 秒超时 | 文档只认 `{"thinking": {"type": "disabled"}}` | 探测当天 `mimo-v2.5` 对任何请求都返回 HTTP 500，改用 `mimo-v2.5-pro` 验证：关思考 2900 字 11 秒；开思考 600 字 17 秒 |

- 小米不认 `reasoning_effort`（`mimo-v2.5-pro` 同样只认 `thinking`）；Deepseek 两种都认。设置页的「额外请求字段」就是为这种各家私有开关准备的。
- `scripts/tts/translate_read.sh` 新增 `long` 用例：约 2850 字、分节编号的选区，判据是输出尾部保留了最后一节的编号（数字可能被写成「十二」或 twelve，目标语言随设置），用来抓输出被截断。开发版应用实测（Cerebras，目标语言当时设为 zh-CN）：不发开关 4 秒出历史行；在设置页把该端点的推理强度设为「关闭（none）」后 2 秒出历史行，均为 2870 字，第十二节在。五次运行里有两次没出历史行，原因是脚本自身：上一轮 2870 字的朗读要读十来分钟，朗读进行中再按朗读热键是「停止」而不是「开始」（`tts/controller.rs`），热键被当成了停止。脚本已改为：注入前以 HUD 窗口是否在窗口列表里判断有没有朗读在进行，有则先停；用例判定后也主动停掉本次朗读，避免拖到下一个用例。改后 `--case all`（success / long / toolong / cancel / stop）一次全部通过，success 1 秒、long 2 秒出历史行。

### B.2 译文历史只存本机（2026-09-16 补充）

同步链路本身能透传 `translate_read` 行：客户端上传只按 `error_code` 过滤，服务器把 `mode` 当自由字符串存，事件原样分发给其他设备。问题在用量计数器：服务器每收到一条新记录就把 `text` 长度加进总输入字符数、`llm_invoked` 加进 AI 纠错次数（`sync-server/src/main.rs`），客户端从同步事件和本机设备统计也做同样的累加。译文时长为 0、动辄两三千字，会把概览页的总字数、AI 纠错和字/分钟都推高。今天的测试已经有 12 条译文行（12,580 字、12 次 AI 纠错）上传并计入账户总量，这部分不会自动回退。

要在服务器端排除需要重新编译部署 voicex-sync，服务器很久没升级、是否有 Rust 环境不确定，所以决定译文只存本机：`history_service.rs` 里 `translate_read` 走单独的落库行为，不进 outbox、不加任何计数器，保留期规则和听写记录一致；删除这类行时不发 `history.delete` 事件，因为服务器从没见过它。同步代码不会整表重建本地历史，本机译文行不会丢。

实机验证时发现第二条出口：同步服务每次启动都会把 `seeded_at` 之后的本地记录补进 outbox（`seed_outbox_from_history`），只按 `error_code` 过滤。落库不进 outbox 的译文行，会在下一次启动时被这条路径补传——第一次验证就是这样又上传了一条 36 字的译文（服务器计数 +36 字、+1 次 AI 纠错、+1 次录音）。所以过滤放在同步服务的出口上：`enqueue_history_upsert` 和启动补传都跳过 `translate_read`，落库时的 `enqueue_sync=false` 只是不再多此一举。
